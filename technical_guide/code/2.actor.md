# Actor 与核心模型接口规范

[中文](#chinese) | [English](#english)

本文说明 `src/agent/actor.py` 的统一接口，重点约束三类 Actor 对应的核心模型。模型负责处理输入并输出动作分数，Actor 负责应用动作掩码和选择动作。环境读取、环境交互、额外信息维护和历史数据保存由外部采样流程负责。

## 1. Actor 接收哪些输入

三个 Actor 使用同一个调用入口：

```python
action_mask, logits, actions = actor(
    observations,
    current_infos,
    addtional_infos=additional_info,
    action_mask=external_action_mask,
    deterministic=False,
)
```

`addtional_infos` 是当前代码中的参数名。外部变量可以使用 `additional_info`；调用时将它传给上述参数即可。

| 参数 | 格式 | 内容 |
|---|---|---|
| `observations` | `dict[int, Any]` | 所有列车的官方观测，按整数列车编号组织 |
| `current_infos` | `dict[str, dict[int, Any]]` | 当前官方 info，先按信息类别、再按列车编号读取 |
| `addtional_infos` | `dict[str, Any]` 或 `None` | 外部维护的额外输入，默认 `None` |
| `action_mask` | `dict[int, Tensor]` 或 `None` | 每列车五个动作的允许标记，默认 `None` |
| `deterministic` | 布尔值 | False 时按概率采样，True 时选择概率最大的允许动作 |

`observations`、`current_infos` 和额外信息对应同一个环境时刻。官方 observation 和 info 使用原有格式；地图、列车位置、任务进度等额外数据，通过 `addtional_infos` 提供。额外字典的字段由模型与数据提供方约定，Actor 原样传递。

## 2. 三种 Actor 如何组织模型

| Actor | 构造方式 | 模型组织与调用 |
|---|---|---|
| `IndependentActor` | `IndependentActor(models)` | 接收整数列车编号到模型对象的字典，为每列车调用自己的模型 |
| `ShareNetworkActor` | `ShareNetworkActor(model)` | 接收一个共享模型，遍历观测字典中的列车编号，分别调用同一个模型 |
| `CentralizedActor` | `CentralizedActor(model)` | 接收一个联合模型，一次调用取得所有列车的动作分数 |

所有核心模型继承 `torch.nn.Module`。`IndependentActor` 内部使用 `nn.ModuleDict` 注册各列车模型，PyTorch 可以统一收集参数、保存权重和移动设备。外部字典使用整数编号，内部存储键转换为字符串，输出仍使用整数编号。

基类 `Actor` 的 `model` 初始为 `None`。基类已实现 `forward` 和 `_get_action`，具体 Actor 实现 `_get_logits`，决定怎样调用核心模型。

## 3. 独立模型与共享模型的规范

### 3.1 输入接口

两类 Actor 使用相同的核心模型调用方式：

```python
model(
    observations,
    current_infos,
    addtional_infos=additional_info,
    agent_id=agent_id,
)
```

模型的 `forward` 接受以下参数：

```python
def forward(
    self,
    observations,
    current_infos,
    *,
    addtional_infos=None,
    agent_id,
):
    ...
```

| 参数 | 模型中的用途 |
|---|---|
| `observations` | 用 `observations[agent_id]` 读取本列车观测 |
| `current_infos` | 用 `current_infos["speed"][agent_id]` 等方式读取辅助信息 |
| `addtional_infos` | 读取该模型约定的额外字段；模型需要处理默认值 `None`，或明确声明必须提供哪些字段 |
| `agent_id` | 指定本次为哪列车输出动作分数 |

模型收到完整的观测和辅助信息字典，自行选择读取范围。独立参数表示各列车使用自己的模型参数；模型是否读取其他列车的信息，在对应实验条件中明确说明。

### 3.2 输出接口

单次调用返回一个 PyTorch 浮点张量，形状固定为 `(5,)`。五项是 logits，即转换成概率之前的动作分数。各项顺序如下：

| 索引 | 对应动作 |
|---|---|
| 0 | `DO_NOTHING`：保持当前运动控制 |
| 1 | `MOVE_LEFT`：选择左侧轨道 |
| 2 | `MOVE_FORWARD`：请求前进 |
| 3 | `MOVE_RIGHT`：选择右侧轨道 |
| 4 | `STOP_MOVING`：请求制动 |

模型直接返回五个分数，概率归一化和动作采样由 Actor 完成。分数可以为正、零或负，全部为有限数值。模型输出保留梯度，供训练时反向传播。

### 3.3 构造方式

独立 Actor 为每列车使用不同的模型实例；各实例可以具有相同网络结构，但参数独立。

```python
from src.agent.actor import IndependentActor

actor = IndependentActor({
    0: TrainPolicy(...),
    1: TrainPolicy(...),
})
```

共享 Actor 只创建一个模型，所有列车使用同一套参数，通过 `agent_id` 选择对应输入。

```python
from src.agent.actor import ShareNetworkActor

actor = ShareNetworkActor(TrainPolicy(...))
```

`TrainPolicy` 表示团队实现的核心模型类，`...` 表示该模型的构造参数。当前共享 Actor 按列车逐次调用，模型每次输出指定列车的五个分数。

## 4. 中央调度模型的规范

### 4.1 输入接口

中央 Actor 一次把全部信息交给模型，调用时使用以下参数：

```python
model(
    observations,
    current_infos,
    addtional_infos=additional_info,
)
```

模型的入口为：

```python
def forward(self, observations, current_infos, *, addtional_infos=None):
    ...
```

模型自行组织所有列车的数据，可以组合全局特征或让列车特征之间交换信息，最后输出各列车的动作分数。

### 4.2 输出接口

返回 `dict[int, Tensor]`：键是整数列车编号，每个值是形状为 `(5,)` 的浮点 logits 张量。模型内部可以使用“列车数量 × 5”的张量计算，返回时按实际列车编号整理。

```python
import torch

logits = {
    0: torch.tensor([0.0, -1.0, 2.0, 0.5, 1.0]),
    1: torch.tensor([0.0, 1.0, 0.5, 2.0, -1.0]),
}
```

上述张量仅用于说明输出格式。实际模型返回网络计算的张量，保留从参数到输出的梯度。模型说明中注明支持的列车数量范围，方便在不同场景中使用。

中央模型联合计算分数后，当前 Actor 为每列车分别建立动作分布并选择动作。需要按照先后顺序生成相互依赖动作的方案，后续再扩展动作选择流程。

### 4.3 构造方式

```python
from src.agent.actor import CentralizedActor

actor = CentralizedActor(JointPolicy(...))
```

`JointPolicy` 表示满足上述联合输出规范的模型类。

## 5. 动作掩码和返回结果

`action_mask` 由外部计算，每列车对应一个形状为 `(5,)` 的 `torch.bool` 张量。True 表示允许选择，False 表示屏蔽。掩码与 logits 字典具有相同的列车编号，每列车至少保留一个允许动作。

Actor 使用 TorchRL 的 `MaskedCategorical` 应用掩码并选择动作。计算时会将每列车的掩码移到相应 logits 所在的设备。未传入掩码时，Actor 根据 logits 创建相同形状、相同设备、全为 True 的掩码。

| 返回值 | 格式 | 含义 |
|---|---|---|
| `action_mask` | `dict[int, Tensor]` | 外部传入的掩码，或自动生成的全 True 掩码 |
| `logits` | `dict[int, Tensor]` | 所有列车的原始动作分数 |
| `actions` | `dict[int, int]` | 列车编号到动作编号的字典，供 `env.step(actions)` 使用 |

三个结果按同一组列车编号对应。独立 Actor 根据模型字典决定输出列车，共享 Actor 根据观测字典决定输出列车，中央 Actor 根据联合模型返回的字典决定输出列车。调用方确保模型集合、观测和外部掩码覆盖需要控制的列车。

## 6. 模型共同遵守的约定

| 项目 | 要求 |
|---|---|
| 输入处理 | 模型内部负责字段选择、数据转换和特征处理 |
| 输出形状 | 每列车输出 `(5,)` 的浮点 logits 张量，顺序保持固定 |
| 梯度 | 直接返回网络计算结果；保留梯度，支持反向传播 |
| 设备 | 输入张量与模型参数使用兼容设备；调用方可通过 `actor.to(device)` 移动模型 |
| 缺失信息 | 处理观测为 `None` 的情况；需要额外字段时明确说明要求 |
| 输入说明 | 记录所需观测类型、特征长度、辅助字段、额外字段及其他列车信息范围 |
| 历史计算 | 使用传入的数据计算，训练时能够根据保存的历史输入重新前向计算 |

模型输出使用 `.detach()`、转换成 NumPy，或用 `torch.tensor(existing_tensor)` 重新包装，会切断原有梯度。这类处理用于外部数据保存；模型训练入口保留原计算过程。采样是否关闭梯度由调用方决定。

`deterministic` 控制动作选择方式。模型的训练和评估模式使用 `actor.train()`、`actor.eval()` 设置，两项分别管理。

## 7. 采样时怎样维护额外信息

下面是已约定的采样流程，具体采样器后续实现。每局 reset 后初始化 `additional_info`，每步决策使用当前值；`env.step(actions)` 后，调用可选更新函数生成下一步的值。

```python
next_observations, rewards, dones, next_infos = env.step(actions)

next_additional = (
    next_additional_info(additional_info, env)
    if next_additional_info is not None
    else additional_info
)
```

`next_additional_info` 接收上一轮额外信息和动作执行后的环境，返回下一轮额外信息。更新函数为 None 时保持原值；额外信息原本为 None 时继续保持 None。提供了更新函数时，它可以处理初始额外信息为 None 的情况。

下一轮使用 `next_observations`、`next_infos` 和 `next_additional` 调用 Actor。额外信息的初始化、更新和任务进度维护都由外部流程负责。

保存训练样本时，记录动作前的观测、`current_infos`、额外信息、实际使用的掩码、动作和旧动作对数概率。可变数据保存独立副本，更新函数也应返回新数据，保留已经保存的历史值。后续训练用历史输入重新计算 logits；当前 Actor 的返回值保持为掩码、logits 和动作，训练记录与 TorchRL 适配由采样模块组织。

# Actor and Core Model Interface Specification

This document describes the common interface in `src/agent/actor.py`, focusing on the core models used by the three Actor classes. The model processes inputs and produces action scores. The Actor applies the action mask and selects actions. The external sampling process reads and steps the environment, maintains additional information, and saves historical data.

## 1. Actor Inputs

All three Actors use the same entry point:

```python
action_mask, logits, actions = actor(
    observations,
    current_infos,
    addtional_infos=additional_info,
    action_mask=external_action_mask,
    deterministic=False,
)
```

`addtional_infos` is the parameter name in the current code. The external variable may be named `additional_info`; pass it to the parameter shown above.

| Parameter | Format | Content |
|---|---|---|
| `observations` | `dict[int, Any]` | Official observations for all trains, keyed by integer train ID |
| `current_infos` | `dict[str, dict[int, Any]]` | Current official info, accessed first by information category and then by train ID |
| `addtional_infos` | `dict[str, Any]` or `None` | Additional inputs maintained externally; defaults to `None` |
| `action_mask` | `dict[int, Tensor]` or `None` | Five action permission flags per train; defaults to `None` |
| `deterministic` | Boolean | False samples from the distribution; True selects the allowed action with the highest probability |

Observations, current info, and additional information must describe the same environment instant. Keep official observation and info formats. Supply extra data such as the map, train positions, and task progress through `addtional_infos`. The model and data provider agree on the extra dictionary's fields; the Actor forwards the dictionary unchanged.

## 2. How the Three Actors Organize Models

| Actor | Construction | Model organization and calls |
|---|---|---|
| `IndependentActor` | `IndependentActor(models)` | Receives a dictionary from integer train IDs to models and calls each train's own model |
| `ShareNetworkActor` | `ShareNetworkActor(model)` | Receives one shared model and calls it separately for each train ID in the observation dictionary |
| `CentralizedActor` | `CentralizedActor(model)` | Receives one joint model and obtains all trains' action scores in one call |

All core models inherit from `torch.nn.Module`. `IndependentActor` registers its models in an `nn.ModuleDict`, allowing PyTorch to collect parameters, save weights, and move devices together. The external dictionary uses integer IDs. Internal keys are converted to strings, while output keys remain integers.

The base `Actor` initially sets `model` to `None`. It implements `forward` and `_get_action`. Concrete Actors implement `_get_logits` to determine how to call the core model.

## 3. Independent and Shared Model Specification

### 3.1 Input Interface

Both Actor types call their core models in the same way:

```python
model(
    observations,
    current_infos,
    addtional_infos=additional_info,
    agent_id=agent_id,
)
```

The model's `forward` accepts these parameters:

```python
def forward(
    self,
    observations,
    current_infos,
    *,
    addtional_infos=None,
    agent_id,
):
    ...
```

| Parameter | Use inside the model |
|---|---|
| `observations` | Read this train's observation with `observations[agent_id]` |
| `current_infos` | Read auxiliary information with expressions such as `current_infos["speed"][agent_id]` |
| `addtional_infos` | Read the extra fields required by the model; handle the default `None` or explicitly document required fields |
| `agent_id` | Identifies the train whose action scores are being computed |

The model receives the full observation and information dictionaries and chooses which entries to read. Independent parameters mean that each train has its own model parameters. State explicitly in the experiment conditions whether a model reads other trains' information.

### 3.2 Output Interface

Each call returns a floating-point PyTorch tensor of shape `(5,)`. These five values are logits: action scores before conversion to probabilities. Their order is fixed:

| Index | Action |
|---|---|
| 0 | `DO_NOTHING`: retain the current movement control |
| 1 | `MOVE_LEFT`: choose the left track |
| 2 | `MOVE_FORWARD`: request forward movement |
| 3 | `MOVE_RIGHT`: choose the right track |
| 4 | `STOP_MOVING`: request braking |

Return the five scores directly. The Actor normalizes probabilities and samples actions. Scores may be positive, zero, or negative and must all be finite. Keep their gradients for training through backpropagation.

### 3.3 Construction

An independent Actor uses a separate model instance for each train. Instances may share the same network architecture, with independent parameters.

```python
from src.agent.actor import IndependentActor

actor = IndependentActor({
    0: TrainPolicy(...),
    1: TrainPolicy(...),
})
```

A shared Actor creates one model. All trains use its parameters, with `agent_id` selecting the relevant inputs.

```python
from src.agent.actor import ShareNetworkActor

actor = ShareNetworkActor(TrainPolicy(...))
```

`TrainPolicy` represents the team's core model class, and `...` represents its constructor arguments. The current shared Actor calls the model once per train, with each call returning that train's five scores.

## 4. Centralized Model Specification

### 4.1 Input Interface

The centralized Actor supplies all inputs to its model in one call:

```python
model(
    observations,
    current_infos,
    addtional_infos=additional_info,
)
```

The model entry point is:

```python
def forward(self, observations, current_infos, *, addtional_infos=None):
    ...
```

The model organizes all trains' data, combines global features or exchanges information between train features, and produces action scores for each train.

### 4.2 Output Interface

Return `dict[int, Tensor]`, with integer train IDs as keys and floating-point logits tensors of shape `(5,)` as values. The model may compute using a tensor of shape “number of trains × 5” internally, then organize the output by actual train ID.

```python
import torch

logits = {
    0: torch.tensor([0.0, -1.0, 2.0, 0.5, 1.0]),
    1: torch.tensor([0.0, 1.0, 0.5, 2.0, -1.0]),
}
```

These tensors illustrate the output format. In a real model, return tensors computed by the network and retain gradients from parameters to outputs. Document the supported range of train counts so that the model can be used in different scenarios.

After the centralized model jointly computes the scores, the current Actor constructs a separate action distribution for each train and selects its action. Methods that generate mutually dependent actions in sequence require a later extension to the action selection process.

### 4.3 Construction

```python
from src.agent.actor import CentralizedActor

actor = CentralizedActor(JointPolicy(...))
```

`JointPolicy` represents a model class meeting the joint output specification above.

## 5. Action Masks and Return Values

Compute `action_mask` externally. Each train must have a `torch.bool` tensor of shape `(5,)`. True allows an action; False masks it out. The mask and logits dictionaries must have the same train IDs, and each train must retain at least one allowed action.

The Actor uses TorchRL's `MaskedCategorical` to apply the mask and select actions. During computation, each train's mask is moved to the device of its logits. When no mask is supplied, the Actor creates an all-True mask with the same shape and device as the logits.

| Return value | Format | Meaning |
|---|---|---|
| `action_mask` | `dict[int, Tensor]` | Supplied mask or automatically generated all-True mask |
| `logits` | `dict[int, Tensor]` | Raw action scores for all trains |
| `actions` | `dict[int, int]` | Train ID to action ID dictionary, ready for `env.step(actions)` |

All three results use the same set of train IDs. The independent Actor determines output trains from its model dictionary, the shared Actor from the observation dictionary, and the centralized Actor from the joint model's output dictionary. The caller ensures that models, observations, and external masks cover the trains being controlled.

## 6. Common Model Requirements

| Item | Requirement |
|---|---|
| Input processing | Select fields, convert data, and process features inside the model |
| Output shape | Return floating-point logits of shape `(5,)` per train in the fixed action order |
| Gradients | Return network results directly and retain gradients for backpropagation |
| Device | Use compatible devices for inputs and parameters; callers can move models with `actor.to(device)` |
| Missing information | Handle observations that are `None`; document required extra fields |
| Input documentation | Record required observation types, feature lengths, auxiliary fields, extra fields, and access to other trains' information |
| Historical computation | Compute from supplied data so that training can repeat a forward pass using saved historical inputs |

Calling `.detach()`, converting outputs to NumPy, or wrapping them with `torch.tensor(existing_tensor)` disconnects the original gradients. Use those operations when saving data externally. Keep the original computation graph at the model's training entry point. The caller decides whether to disable gradients during sampling.

`deterministic` controls action selection. Set training or evaluation mode with `actor.train()` or `actor.eval()`. These settings have separate responsibilities.

## 7. Maintaining Additional Information During Sampling

The following sampling flow has been agreed on; the concrete sampler will be implemented later. Initialize `additional_info` after each reset and use its current value for each decision. After `env.step(actions)`, call the optional update function to produce the next value.

```python
next_observations, rewards, dones, next_infos = env.step(actions)

next_additional = (
    next_additional_info(additional_info, env)
    if next_additional_info is not None
    else additional_info
)
```

`next_additional_info` receives the previous additional information and the environment after the action, then returns the next additional information. When the function is None, preserve the previous value; if that value is None, it stays None. An available update function can handle an initial value of None.

Call the Actor on the next iteration with `next_observations`, `next_infos`, and `next_additional`. The external process initializes and updates extra information and maintains task progress.

When saving training samples, record the observations before the action, `current_infos`, additional information, the mask actually used, the action, and its old log probability. Save independent copies of mutable data. The update function should also return new data so that saved historical values remain intact. Later training recomputes logits from historical inputs. The Actor continues returning the mask, logits, and actions; the sampling module organizes training records and TorchRL adaptation.

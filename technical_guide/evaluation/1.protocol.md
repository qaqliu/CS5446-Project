# 统一评估协议

[中文](#chinese) | [English](#english)

所有方法（PPO、通信、value-based、启发式）都在同一组没见过的地图上评估，结果可以直接放进同一张表。训练方式不限，只要不使用验证/测试地图的 seed。

## 1. 评估设置

| 项目 | 设置 |
|---|---|
| 地图 | 比赛（NeurIPS 2020）评估生成器：城市数 = n//10+2，边长由公式决定（5 车 25×25、10 车 29×29、20 车 32×32、50 车 40×40、100 车 50×50），城际最多 2 条轨道，城内最多 2 对轨道，随机城市分布 |
| 任务 | 起点到终点，无中途站；所有列车最大速度 1；无故障；列车可以在任何地方停车等待 |
| 时限 | 比赛公式 t_max = 8 (w + h + n / cities) |
| 验证地图 | seed 2000–2019，只用于选 checkpoint 和调参 |
| 测试地图 | seed 1000–1019，只用于报告结果 |
| 测试规模 | 5 / 10 / 20 / 50 车（可选 100 车）；固定车数的模型（独立网络、train ID）只在训练规模测试 |
| 选 checkpoint | 在训练规模的验证地图上按 competition score 选最好的；更大规模不参与选择 |
| 每张测试图 | 3 个 sampled episode（主要结果）+ 1 个 deterministic episode |
| 指标 | 到站率、competition score（1 − 平均到站时间/t_max，未到站按 t_max）、死锁率（团队 DeadlockChecker）、卡住率、发车率、延误基尼系数、makespan |

## 2. 常用命令

```bash
# 训练（训练地图策略写在 YAML 的 training_maps 里）
python -m scripts.train --config config/protocol/shared_ppo_random_maps.yaml --seed 42 --out results/runs/shared_seed42
# 多个配方 × 多个 seed 并行训练并评估
python -m scripts.run_experiments --configs config/protocol/*.yaml --seeds 42 43 44 --out results/runs --jobs 6
# 评估任意 checkpoint 目录
python -m scripts.evaluate results/runs
# 启发式 baseline（random / shortest path / departure cap / prioritized planning）
python -m scripts.evaluate_baselines --out results/baselines
# 汇总表格和图
python -m scripts.compare results/runs results/baselines --out results/report
```

## 3. 训练地图策略

```yaml
training_maps:
  generator: competition   # 用比赛公式按车数生成地图
  mode: random             # fixed | random | pool
  pool_size: 20            # pool 模式的地图数量
  sizes: [5, 10, 20]       # 可选：每局随机车数（仅 episode-based ppo）
```

要加新的训练策略，扩展 `scripts/train.py` 的 `make_reset`。评估不需要改。

## 4. 新方法如何接入

1. 训练时不要用验证/测试 seed（`scripts/train.py` 会检查）。
2. 报告训练预算（环境步数，`scripts/train.py` 会写进 checkpoint 的 `env_steps`）；对比表默认约 3M 步、3 个 seed。
3. checkpoint 存 `{"epoch", "config", "actor"}`，或者提供 `--loader module:function`，返回 `(policy_factory, config)`，`policy_factory(deterministic)` 返回一个 `(env, observations, infos, masks, decisions) -> actions` 的策略。value-based 模型可以用这个接口接入。

# Shared Evaluation Protocol

Every method (PPO, communication, value-based, heuristics) is scored on the same unseen maps, so results go into one table. Training is free as long as it never uses validation or test map seeds.

## 1. Evaluation Settings

| Item | Setting |
|---|---|
| Maps | NeurIPS 2020 evaluation generator: cities = n//10+2, square size from the formula (5 trains 25×25, 10 → 29×29, 20 → 32×32, 50 → 40×40, 100 → 50×50), at most 2 rails between cities and 2 rail pairs in a city, random city placement |
| Task | Origin to destination, no scheduled intermediate stations, all trains max speed 1, no malfunctions; trains may stop and wait anywhere |
| Episode limit | Competition formula t_max = 8 (w + h + n / cities) |
| Validation maps | Seeds 2000–2019, only for checkpoint selection and tuning |
| Test maps | Seeds 1000–1019, only for reported results |
| Test sizes | 5 / 10 / 20 / 50 trains (100 optional); fixed-size models (independent networks, train-ID input) are tested only at their training size |
| Checkpoint selection | Best validation competition score at the training size(s); larger sizes never take part |
| Per test map | 3 sampled episodes (headline) + 1 deterministic episode |
| Metrics | Completion, competition score (1 − mean arrival time / t_max, t_max for trains that never arrive), deadlock rate (team DeadlockChecker), stuck rate, departure rate, delay Gini, makespan |

Sources: Laurent et al. 2021 (competition setup, Sec. 2.3 and App. B) and Mohanty et al. 2020 (train/validation/test protocol, Sec. 4.1). Differences from the competition: at most 100 trains instead of 6,256, no malfunctions, Flatland 4.3 timetables, per-size means instead of a summed score, and no compute time limits.

## 2. Commands

```bash
# Train (the training-map strategy is the YAML's training_maps block)
python -m scripts.train --config config/protocol/shared_ppo_random_maps.yaml --seed 42 --out results/runs/shared_seed42
# Several recipes x seeds in parallel, then evaluate
python -m scripts.run_experiments --configs config/protocol/*.yaml --seeds 42 43 44 --out results/runs --jobs 6
# Evaluate any folder of checkpoint directories
python -m scripts.evaluate results/runs
# Heuristic baselines (random / shortest path / departure cap / prioritized planning)
python -m scripts.evaluate_baselines --out results/baselines
# Tables and charts
python -m scripts.compare results/runs results/baselines --out results/report
```

## 3. Training-Map Strategies

```yaml
training_maps:
  generator: competition   # map from the competition formula for the train count
  mode: random             # fixed | random | pool
  pool_size: 20            # number of maps in pool mode
  sizes: [5, 10, 20]       # optional: new train count each episode (episode-based ppo only)
```

To add a strategy, extend `make_reset` in `scripts/train.py`. Evaluation does not change.

## 4. Adding a New Method

1. Never train on validation or test seeds (`scripts/train.py` checks this).
2. Report the training budget in environment steps (`scripts/train.py` saves `env_steps` in every checkpoint). Comparison tables use about 3M steps and 3 seeds by default.
3. Save checkpoints as `{"epoch", "config", "actor"}`, or pass `--loader module:function` returning `(policy_factory, config)`, where `policy_factory(deterministic)` returns a policy `(env, observations, infos, masks, decisions) -> actions`. Value-based models can plug in this way.

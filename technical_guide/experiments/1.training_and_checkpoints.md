# 训练、实验与 checkpoint

[中文](#chinese) | [English](#english)

实验配方都在 `config/protocol/`，一个 YAML 就是一个方法。评估方式见 [统一评估协议](../evaluation/1.protocol.md)。

## 1. 训练命令

```bash
# 训练一个配方、一个 seed
python -m scripts.train --config config/protocol/shared_ppo_random_maps.yaml --seed 42 --out results/runs/shared_ppo_random_maps_seed42
# 多个配方 × 多个 seed 并行训练，训练完自动评估
python -m scripts.run_experiments --configs config/protocol/*.yaml --seeds 42 43 44 --out results/runs --jobs 6
```

run 目录名约定为 `<配方名>_seed<N>`：配方名就是 YAML 的文件名，报告和 checkpoint 文件夹都用这个名字。每个配方末尾有一个 `report:` 块，报告和 checkpoint 清单从这里读名称和分组：

```yaml
report:
  label: Shared PPO, 15M (10M + 5M with LR decay)   # 报告里显示的名称
  group: Training budget and schedule               # 报告里的分组（每组回答一个问题）
  order: 2                                          # 组内顺序
  changes:                                          # 和参考配方 shared_ppo_random_maps 不同的设置（报告里加粗）
    LR schedule: Linear decay to 0
```

新加配方时复制一个最接近的 YAML，只改要比较的字段和 `report:` 块。CPU 上一个 5 车的 3M 步配方需要几个小时；`--jobs` 不要超过 CPU 核数。

## 2. 训练地图策略

```yaml
training_maps:
  generator: competition   # 用比赛公式按车数生成地图（和测试地图同一分布）
  mode: random             # fixed | random | pool
  pool_size: 20            # pool 模式的地图数量
  sizes: [5, 10, 20]       # 可选：每局随机车数（仅 episode-based ppo）
```

`random` 每局换一张新地图（推荐），`fixed` 整个训练只用一张图，`pool` 每局从固定的 20 张图里选一张。要加新的训练策略，扩展 `scripts/train.py` 的 `make_reset`。

## 3. 从已有 checkpoint 继续训练（curriculum）

在 YAML 里写 `init_from`，`{seed}` 会换成训练 seed。只加载 actor/critic 权重，学习率和 entropy 按新 YAML 的设置重新开始；训练步数会接着累计。

```yaml
init_from: checkpoints/shared_ppo_random_maps_10M/seed{seed}/final.pt
number_of_agents: 10        # 在更大的地图上继续
```

`shared_ppo_15M_lr_decay`、`shared_ppo_15M_curriculum10`、`shared_ppo_13M_curriculum20` 就是这样从 10M 模型继续的，需要先下载下面的 checkpoint。

## 4. 已训练的模型

所有已评估的模型放在 Google Drive（链接见团队群），清单在 [docs/checkpoints.md](../../docs/checkpoints.md)（压缩包里也有一份 `MANIFEST.md`）。下载后放到仓库根目录的 `checkpoints/`（已在 .gitignore 里）：

```
checkpoints/
  MANIFEST.md                      # 每个方法：配方、seed、选中的 epoch、训练步数、测试结果
  <配方名>/seed42/best.pt          # 验证集选出的 checkpoint，报告里的数字都用它
  <配方名>/seed42/final.pt         # 最后一个 checkpoint，继续训练时用作 init_from
  <配方名>/seed42/config.yaml      # 实际训练配置
  <配方名>/seed42/evaluation.csv   # 报告数字背后的每个验证/测试 episode
```

`<配方名>_with_cap` 是 RL + departure cap 混合：没有新权重，用对应配方的 `best.pt`，每个车数选的 cap 写在清单里。代码里加载策略：`src.eval.runner.load_actor_checkpoint("checkpoints/<配方名>/seed42/best.pt")`。打包新的 checkpoint：`python -m scripts.export_checkpoints results/runs --out checkpoints`（同时更新 `docs/checkpoints.md`）。

# Training, Experiments, and Checkpoints

Recipes live in `config/protocol/`; one YAML is one method. Scoring is described in the [Shared Evaluation Protocol](../evaluation/1.protocol.md#english).

## 1. Training Commands

```bash
# Train one recipe with one seed
python -m scripts.train --config config/protocol/shared_ppo_random_maps.yaml --seed 42 --out results/runs/shared_ppo_random_maps_seed42
# Several recipes x seeds in parallel, then evaluate automatically
python -m scripts.run_experiments --configs config/protocol/*.yaml --seeds 42 43 44 --out results/runs --jobs 6
```

Name run directories `<recipe>_seed<N>`: the recipe is the YAML file name, and the report and checkpoint folders use the same name. Each recipe ends with a `report:` block that the report and checkpoint list read for its name and group:

```yaml
report:
  label: Shared PPO, 15M (10M + 5M with LR decay)   # name shown in the report
  group: Training budget and schedule               # report section (each answers one question)
  order: 2                                          # order within the section
  changes:                                          # settings that differ from shared_ppo_random_maps (bold in the report)
    LR schedule: Linear decay to 0
```

To add a recipe, copy the closest YAML and change only the fields you are testing plus its `report:` block. On CPU a 3M-step recipe at 5 trains takes a few hours; keep `--jobs` at or below the number of CPU cores.

## 2. Training-Map Strategies

```yaml
training_maps:
  generator: competition   # map from the competition formula for the train count (same distribution as the test maps)
  mode: random             # fixed | random | pool
  pool_size: 20            # number of maps in pool mode
  sizes: [5, 10, 20]       # optional: new train count each episode (episode-based ppo only)
```

`random` uses a new map every episode (recommended), `fixed` one map for the whole run, and `pool` one of 20 fixed maps per episode. To add a strategy, extend `make_reset` in `scripts/train.py`.

## 3. Continuing from a Checkpoint (Curriculum)

Set `init_from` in the YAML; `{seed}` becomes the training seed. Only actor/critic weights are loaded; learning rate and entropy restart from the new YAML's settings, and the environment-step count continues.

```yaml
init_from: checkpoints/shared_ppo_random_maps_10M/seed{seed}/final.pt
number_of_agents: 10        # continue on larger maps
```

`shared_ppo_15M_lr_decay`, `shared_ppo_15M_curriculum10`, and `shared_ppo_13M_curriculum20` continue the 10M model this way, so download the checkpoints below first.

## 4. Trained Checkpoints

Every evaluated model is on Google Drive (link in the team chat). The list is in [docs/checkpoints.md](../../docs/checkpoints.md) (the archive also contains it as `MANIFEST.md`). Put the download at the repo root as `checkpoints/` (git-ignored):

```
checkpoints/
  MANIFEST.md                     # per method: recipe, seeds, selected epochs, budget, held-out results
  <recipe>/seed42/best.pt         # checkpoint selected on validation; all reported numbers use it
  <recipe>/seed42/final.pt        # last checkpoint; use it as init_from to continue training
  <recipe>/seed42/config.yaml     # resolved training config
  <recipe>/seed42/evaluation.csv  # every validation/test episode behind the reported numbers
```

`<recipe>_with_cap` folders are the RL + departure-cap hybrid: no new weights, they reuse that recipe's `best.pt`, and the list gives the cap chosen per train count. Load a policy in code with `src.eval.runner.load_actor_checkpoint("checkpoints/<recipe>/seed42/best.pt")`. To package new checkpoints: `python -m scripts.export_checkpoints results/runs --out checkpoints` (also refreshes `docs/checkpoints.md`).

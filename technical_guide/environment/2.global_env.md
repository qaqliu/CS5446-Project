# 从 env 读取地图、列车和任务信息

[中文](#chinese) | [English](#english)

本文介绍 Flatland 4.3.0 的 `RailEnv` 对象中经常需要读取的字段。`env` 表示当前铁路环境，保存整张地图、全部列车、本局任务和运行进度。模型可以根据自己的需要读取这些官方信息。创建环境的方法见 [Flatland 使用教程](1.flatland_overview.md)，官方 observation 和 info 的格式见 [状态与动作说明](3.state_and_action.md)。

## 1. env 中的信息怎样组织

环境创建后，先调用 `env.reset()`，再读取地图和列车任务。地图、列车数量或任务重新生成时，字段内容也会更新。每次 `env.step(actions)` 后，列车位置、状态和本局时间变为动作执行后的值。

| 信息类别 | 常用读取入口 | 内容 |
|---|---|---|
| 地图 | `env.width`、`env.height`、`env.rail` | 地图尺寸和轨道连接 |
| 全部列车 | `env.agents` | 每列车的位置、朝向、状态、速度和任务 |
| 地图内列车位置 | `env.agent_positions` | 每个格子上的列车编号 |
| 目标距离 | `env.distance_map` | 各列车从不同位置和朝向到终点的最短轨道距离 |
| 本局进度 | `env._elapsed_steps`、`env._max_episode_steps`、`env.dones` | 当前时间、整局时限和结束标记 |
| 官方辅助信息 | `env.get_info_dict()` | 当前的动作需求、故障计数、速度和运行状态 |
| 环境设置 | `env.remove_agents_at_target`、`env.acceleration_delta`、`env.braking_delta` | 到站移除方式、加速和制动参数 |

`env` 是一个 Python 对象，通过属性和方法读取信息。`env.reset()` 和 `env.step()` 返回的 observation、info 字典提供了其中的一部分数据；需要地图或完整任务时，继续从上表中的入口读取。模型和 Actor 对环境只读，环境的重置和推进由外部交互流程负责。

## 2. 地图尺寸和轨道连接

### 2.1 地图尺寸

| 字段 | 格式 | 含义 |
|---|---|---|
| `env.width` | 整数 | 地图的列数，即横向格子数量 |
| `env.height` | 整数 | 地图的行数，即纵向格子数量 |
| `env.rail.grid` | 二维 NumPy 数组，形状为 `(height, width)` | 每个格子的轨道连接编码 |

位置统一写成 `(row, column)`，先行后列。行列索引从 0 开始，行号向下增加，列号向右增加。例如 `(3, 7)` 表示第 4 行、第 8 列。地图宽高分别为 30 时，合法行号和列号都在 0 到 29 之间。

`env.rail.grid` 的元素使用 16 位无符号整数保存轨道连接。每个整数编码了四种进入朝向与四种离开方向之间的连接关系，共 16 项；值为 0 表示该格没有轨道连接。判断某列车能往哪里走时，使用下面的查询方法读取具体出口。

### 2.2 位置和朝向的组合

官方把位置与朝向组合成一个 `configuration`，格式为 `((row, column), direction)`。例如 `((3, 7), 1)` 表示列车位于第 4 行、第 8 列，朝东。

| 方向编号 | 朝向 |
|---|---|
| 0 | 北 |
| 1 | 东 |
| 2 | 南 |
| 3 | 西 |

### 2.3 查询某个朝向对应的轨道出口

调用 `env.rail.get_transitions(configuration)`，返回按北、东、南、西排列的四个连接标记。每项为 1 表示存在对应出口，为 0 表示没有。这个查询考虑列车的进入朝向，同一个格子在不同朝向下可能有不同结果。

```python
configuration = ((3, 7), 1)
exits = env.rail.get_transitions(configuration)
print(exits)
```

例如返回 `(0, 1, 1, 0)`，表示该位置和朝向下可以沿轨道向东或向南离开。这四项是地图上的绝对方向。环境动作中的左、前、右以列车朝向为参照，计算动作掩码时还需要按官方动作语义进行转换。

| 方法 | 返回内容 |
|---|---|
| `env.rail.get_transitions(configuration)` | 指定位置和朝向下允许的四个出口 |
| `env.rail.get_full_transitions(row, column)` | 指定格子的完整整数连接编码 |
| `env.rail.is_valid_configuration(configuration)` | 判断该位置是否在地图内，并且该朝向下是否存在轨道出口 |

这些查询提供地图连接信息。下一格是否被占用、其他列车本步会选择什么动作，由列车状态和环境的资源处理进一步决定。

## 3. 访问全部列车

`env.agents` 是列车对象列表。在标准 `RailEnv` 中，列车编号从 0 开始，`env.agents[train_id]` 取得对应对象。每个对象的 `handle` 保存该列车编号。

| 入口 | 返回内容 |
|---|---|
| `env.agents` | 所有列车对象 |
| `env.get_agent_handles()` | 所有列车编号的列表 |
| `env.get_num_agents()` | 当前列车对象的实际数量，等于 `len(env.agents)` |
| `env.number_of_agents` | 环境配置中的列车生成数量 |

读取当前列车集合时使用 `env.agents` 或 `env.get_num_agents()`；记录生成设置时可以读取 `env.number_of_agents`。

```python
for agent in env.agents:
    print(agent.handle, agent.state, agent.current_configuration)
```

后文中的 `agent` 均表示某列车的对象，例如 `agent = env.agents[0]`。

## 4. 列车的当前位置、状态和速度

### 4.1 位置字段

| 字段 | 格式 | 含义 |
|---|---|---|
| `agent.initial_configuration` | 位置与朝向的组合 | 列车的初始位置和朝向 |
| `agent.current_configuration` | 位置与朝向的组合，或 `None` | 当前地图内的位置和朝向 |
| `agent.old_configuration` | 位置与朝向的组合，或 `None` | 最近一次 step 开始时的位置和朝向 |
| `agent.target_configuration` | 位置与朝向的组合，或 `None` | 完成任务时实际到达的终点配置 |

`None` 表示当前没有对应值。列车尚未进入地图时，`current_configuration` 为 `None`；开启到站移除后，完成的列车也会变为 `None`。因此先查看 `agent.state`，再解释位置字段。

```python
agent = env.agents[0]
configuration = agent.current_configuration

if configuration is not None:
    position, direction = configuration
    row, column = position
    print(row, column, direction)
```

如果需要一个用于显示或计算观测的参考位置，可以使用官方的 `virtual_configuration(agent)`：地图外列车使用初始配置，地图内列车使用当前配置，已完成列车使用实际到达配置。参考位置与地图中的真实占用分别处理。

```python
from flatland.envs.agent_utils import virtual_configuration

reference_configuration = virtual_configuration(agent)
```

### 4.2 运行状态

`agent.state` 返回 `TrainState` 枚举。它与官方 `info["state"][train_id]` 表达相同的运行状态。

| 编号 | 状态 | 含义 |
|---|---|---|
| 0 | `WAITING` | 等待达到最早出发时间 |
| 1 | `READY_TO_DEPART` | 已具备出发条件，等待有效出发动作 |
| 2 | `MALFUNCTION_OFF_MAP` | 地图外故障 |
| 3 | `MOVING` | 行驶中 |
| 4 | `STOPPED` | 地图内停车 |
| 5 | `MALFUNCTION` | 地图内故障 |
| 6 | `DONE` | 已到达允许的最终目标配置 |

当前项目关闭故障生成，读取状态时沿用官方枚举。判断列车是否真正完成任务，比较 `agent.state == TrainState.DONE`。这个完成状态表示到达终点，途经站服务情况还需要结合停靠记录判断。

### 4.3 速度与格内进度

| 字段或方法 | 含义 |
|---|---|
| `agent.speed_counter.speed` | 当前速度计的速度值 |
| `agent.speed_counter.max_speed` | 该列车允许的最大速度 |
| `agent.speed_counter.distance` | 当前轨道格内的累计行进进度 |
| `agent.speed_counter.is_cell_entry` | 最近一步是否刚进入一个格子 |
| `agent.speed_counter.is_cell_exit(speed)` | 以给定速度计算下一步是否达到离开当前格子的条件 |

速度单位是每个环境步行进的格数。最大速度为 1 表示每步最多行进一格，最大速度为 0.5 表示通常需要两步行进一格。速度和进度使用 Python 的 `Fraction` 分数类型，展示或转换成模型数值时可以调用 `float()`。

`distance` 表示格内进度，在跨格后更新。速度计读数需要结合运行状态解释：停止或故障状态下，速度计可能仍保存一个非零值。判断某一步是否实际移动时，比较该步前后的位置和进度。

```python
print(float(agent.speed_counter.speed))
print(float(agent.speed_counter.max_speed))
print(float(agent.speed_counter.distance))
```

## 5. 起终点、途经站和时刻表

### 5.1 最终目标

| 字段 | 格式 | 含义 |
|---|---|---|
| `agent.targets` | 位置与朝向组合的集合 | 所有允许的最终到达配置 |
| `agent.target_configuration` | 一个配置，或 `None` | 实际到达的配置，完成前为 `None` |
| `agent.arrival_time` | 整数，或 `None` | 最终到达的环境时间步，完成前为 `None` |

一个终点可以允许多个到达方向，也可以包含多个备选配置。读取目标时保留整个 `targets` 集合。需要知道列车最终选择了哪一个时，读取 `target_configuration`。

### 5.2 任务经过的地点

`agent.waypoints` 保存本列车的任务地点，格式为“列表中的每一项又是一个列表”。外层第一项是起点，最后一项是终点，中间各项表示途经站。每项中的多个 `Waypoint` 表示同一个任务地点允许的停靠位置和朝向。

| 读取方式 | 含义 |
|---|---|
| `agent.waypoints[0]` | 起点对应的配置 |
| `agent.waypoints[1:-1]` | 全部途经站的备选停靠配置 |
| `agent.waypoints[-1]` | 最终目标的备选配置 |
| `waypoint.position` | 某个备选地点的位置，格式为 `(row, column)` |
| `waypoint.direction` | 该备选地点要求的朝向 |

例如，外层有四项，表示起点、两个途经站、终点。某个途经站的内层有三项，表示服务这个站可以在三种备选配置中选择。外层是任务安排，当前环境的运动过程允许跳过途经站；官方奖励根据实际记录判断遗漏停靠和时间偏差。

### 5.3 时间要求

| 字段 | 含义 |
|---|---|
| `agent.earliest_departure` | 本列车最早可以出发的时间步 |
| `agent.latest_arrival` | 本列车最终目标的最晚到达时间步 |
| `agent.waypoints_earliest_departure` | 各任务地点的最早离开时间，与 `waypoints` 外层逐项对应 |
| `agent.waypoints_latest_arrival` | 各任务地点的最晚到达时间，与 `waypoints` 外层逐项对应 |

这些时间都是从本局开始计数的环境时间步。例如最晚到达时间为 50，当前时间为 30，距离规定时间还有 20 步。某项为 `None` 表示该地点没有对应的时间要求：起点通常没有最晚到达时间，终点通常没有最早离开时间。

```python
for alternatives, earliest_departure, latest_arrival in zip(
    agent.waypoints,
    agent.waypoints_earliest_departure,
    agent.waypoints_latest_arrival,
):
    print(alternatives, earliest_departure, latest_arrival)
```

最早出发时间由官方状态机强制执行。途经站停靠、离站时间和晚到情况按官方任务与奖励规则处理，具体实验是否考核这些要求见 [实验环境配置](../setting/1.experiment_variable.md)。

### 5.4 途经站已经完成了吗

列车对象没有一个通用的“下一站编号”或“各站已完成标记”字段。`waypoints` 保存任务安排，`state` 保存当前运行状态，二者本身不足以直接读出完整的历史停靠进度。

使用官方 `DefaultRewards` 时，其内部奖励对象记录到达、离开和经过的状态。以下读取方式依赖该奖励组件及其内部结构：

| 读取位置 | 内容 |
|---|---|
| `env.rewards._proxy.arrivals` | 按列车编号、位置与朝向保存到达时间列表 |
| `env.rewards._proxy.departures` | 按列车编号、位置与朝向保存离开时间列表 |
| `env.rewards._proxy.states` | 按列车编号、位置与朝向保存曾出现的运行状态集合 |

官方奖励结合这些记录判断是否在备选停靠配置出现过 `STOPPED` 状态，以及相应到达和离开时间。更换奖励组件时，先检查它是否提供这些记录；`_proxy` 属于内部字段。这里只列出官方已有记录的读取位置，具体进度判断需要按所用组件处理。

## 6. 查看所有列车占用的位置

`env.agent_positions` 是形状为 `(height, width)` 的二维整数数组。在普通格子轨道场景中，每格保存当前列车编号，空格保存 -1。尚未进入地图的列车不会占用起点；到站移除的列车也不会继续占用终点。

```python
train_id = int(env.agent_positions[3, 7])
if train_id >= 0:
    occupying_agent = env.agents[train_id]
    print(occupying_agent.state)
```

这个数组适合快速查看格子占用。需要列车朝向、速度和完整状态时，通过编号读取对应的列车对象。当前占用表示这一刻的位置，下一步的占用还取决于所有列车共同提交的动作。

## 7. 到最终目标的最短距离

调用 `env.distance_map.get()` 可以取得形状为 `(列车数量, 地图高度, 地图宽度, 4)` 的数组。四个维度分别选择列车、行、列和朝向。数值表示从指定位置与朝向沿轨道到该列车任一允许终点的最短距离。

```python
distances = env.distance_map.get()
configuration = agent.current_configuration

if configuration is not None:
    (row, column), direction = configuration
    distance = distances[agent.handle, row, column, direction]
    print(distance)
```

这里的距离按轨道格数计算。无法到达终点时使用正无穷，Python 中常显示为 `inf`。距离计算考虑轨道连接和朝向，当前其他列车的占用、等待时间、时刻表与途经站停靠要求需要另外考虑。最大速度不同的列车，即使距离相同，完成行程所需时间也会不同。

`env.distance_map.get()` 按官方逻辑计算或复用距离数据。读取最短距离时使用这个方法，避免直接假定底层数组已经完成计算。

## 8. 本局时间、结束标记和运行设置

| 字段 | 含义 |
|---|---|
| `env._elapsed_steps` | 本局已推进的时间步数，reset 后为 0 |
| `env._max_episode_steps` | 本局最大步数，reset 后可读取 |
| `env.dones` | 按列车编号保存结束标记，`"__all__"` 表示整局结束 |
| `env.rewards_dict` | 最近一步的官方奖励字典，按列车编号组织 |
| `env.remove_agents_at_target` | 到达目标后是否将列车从地图移除 |
| `env.acceleration_delta` | 加速参数 |
| `env.braking_delta` | 制动参数 |
| `env.obs_builder` | 当前使用的官方观测生成器对象 |

名称以 `_` 开头的字段属于库内部字段。当前 Flatland 4.3.0 可以按表中位置读取时间，升级库版本时重新核对。

达到全局时限后，环境会把所有列车的结束标记设为 True，包括尚未到站的列车。统计真正到站的列车时使用 `agent.state == TrainState.DONE`。`env.rewards_dict` 保存最近一步的奖励，整局累计回报需要对各步奖励求和。

## 9. 与 observations、current_infos 的对应关系

模型调用中的 `current_infos` 就是官方当前 `info` 字典，只是项目使用了更直观的变量名。需要直接从环境取得它时，可以调用 `env.get_info_dict()`。

| 数据 | 内容与读取范围 |
|---|---|
| `observations[train_id]` | 所选官方观测生成器提供给该列车的观测 |
| `current_infos` | 官方四类辅助信息：动作需求、故障计数、速度和状态 |
| `env` | 完整地图、全部列车对象、任务、时刻表与环境运行数据 |

获取本步动作时，这三项数据应对应同一个环境时刻。`env.step()` 后，环境对象已经更新；保存历史训练数据时，要保存模型实际使用的数值，后续 PPO 更新使用这些历史数据。模型是否读取完整地图或其他列车信息，由所选模型和实验条件决定。

# Reading Map, Train, and Task Information from env

This document introduces commonly used fields of Flatland 4.3.0's `RailEnv`. `env` is the current railway environment, containing the entire map, all trains, episode tasks, and progress. Models can use the official information they need. See [the Flatland tutorial](1.flatland_overview.md) for environment creation and [the state and action guide](3.state_and_action.md) for official observation and info formats.

## 1. How Information Is Organized in env

After creating the environment, call `env.reset()` before reading the map and train tasks. Fields update when the map, train count, or tasks are regenerated. After each `env.step(actions)`, train positions, states, and episode time describe the situation after the actions.

| Information category | Common access points | Content |
|---|---|---|
| Map | `env.width`, `env.height`, `env.rail` | Map dimensions and track connections |
| All trains | `env.agents` | Each train's position, direction, state, speed, and task |
| Train positions on the map | `env.agent_positions` | Train ID occupying each cell |
| Distance to targets | `env.distance_map` | Shortest track distance from different positions and directions to each train's destination |
| Episode progress | `env._elapsed_steps`, `env._max_episode_steps`, `env.dones` | Current time, episode limit, and end flags |
| Official auxiliary information | `env.get_info_dict()` | Current action requirement, malfunction counter, speed, and running state |
| Environment settings | `env.remove_agents_at_target`, `env.acceleration_delta`, `env.braking_delta` | Removal at destinations, acceleration, and braking parameters |

`env` is a Python object whose information is accessed through attributes and methods. The observation and info dictionaries returned by `env.reset()` and `env.step()` expose some of this data. Use the access points above when you need the map or complete tasks. Models and Actors read environment information; the external interaction process resets and advances the environment.

## 2. Map Dimensions and Track Connections

### 2.1 Map Dimensions

| Field | Format | Meaning |
|---|---|---|
| `env.width` | Integer | Number of columns, or horizontal cells |
| `env.height` | Integer | Number of rows, or vertical cells |
| `env.rail.grid` | Two-dimensional NumPy array of shape `(height, width)` | Encoded track connections for each cell |

Positions use `(row, column)`, with the row first. Indices start at 0, rows increase downward, and columns increase to the right. For example, `(3, 7)` means the fourth row and eighth column. With width and height both 30, valid row and column indices range from 0 to 29.

Elements of `env.rail.grid` are unsigned 16-bit integers. Each integer encodes connections between four incoming orientations and four outgoing directions, giving 16 possible connections. A value of 0 means no track connections. Use the queries below to read specific exits when determining where a train can go.

### 2.2 Position and Direction Together

The official environment combines position and direction into a `configuration`, written as `((row, column), direction)`. For example, `((3, 7), 1)` means a train in the fourth row and eighth column, facing east.

| Direction ID | Direction |
|---|---|
| 0 | North |
| 1 | East |
| 2 | South |
| 3 | West |

### 2.3 Querying Track Exits for an Orientation

`env.rail.get_transitions(configuration)` returns four connection flags ordered north, east, south, west. A value of 1 indicates an exit, and 0 indicates no exit. This query accounts for the train's incoming orientation, so different orientations at the same cell can produce different results.

```python
configuration = ((3, 7), 1)
exits = env.rail.get_transitions(configuration)
print(exits)
```

For example, `(0, 1, 1, 0)` allows leaving east or south from that configuration. These flags use absolute map directions. Left, forward, and right actions are relative to the train's orientation, so action mask computation must convert exits according to the official action semantics.

| Method | Result |
|---|---|
| `env.rail.get_transitions(configuration)` | Four allowed exits for the specified position and orientation |
| `env.rail.get_full_transitions(row, column)` | Complete integer connection encoding for the cell |
| `env.rail.is_valid_configuration(configuration)` | Whether the position is inside the map and has a track exit for the given orientation |

These queries describe map connections. Train states and the environment's resource handling further determine whether the next cell is occupied and how other trains' actions affect movement.

## 3. Accessing All Trains

`env.agents` is a list of train objects. In a standard `RailEnv`, IDs start at 0, and `env.agents[train_id]` returns the corresponding object. Each object's `handle` stores its train ID.

| Access point | Result |
|---|---|
| `env.agents` | All train objects |
| `env.get_agent_handles()` | List of all train IDs |
| `env.get_num_agents()` | Actual number of current train objects, equal to `len(env.agents)` |
| `env.number_of_agents` | Number of trains requested in the environment configuration |

Use `env.agents` or `env.get_num_agents()` for the current train collection. Read `env.number_of_agents` when recording generation settings.

```python
for agent in env.agents:
    print(agent.handle, agent.state, agent.current_configuration)
```

In the following sections, `agent` means a train object, for example `agent = env.agents[0]`.

## 4. Current Train Position, State, and Speed

### 4.1 Position Fields

| Field | Format | Meaning |
|---|---|---|
| `agent.initial_configuration` | Position and direction | Initial position and orientation |
| `agent.current_configuration` | Position and direction, or `None` | Current position and orientation on the map |
| `agent.old_configuration` | Position and direction, or `None` | Position and orientation at the start of the most recent step |
| `agent.target_configuration` | Position and direction, or `None` | Destination configuration actually reached when completing the task |

`None` means there is currently no corresponding value. Before a train enters the map, its `current_configuration` is `None`. With removal at destinations enabled, completed trains also have `None`. Check `agent.state` before interpreting position fields.

```python
agent = env.agents[0]
configuration = agent.current_configuration

if configuration is not None:
    position, direction = configuration
    row, column = position
    print(row, column, direction)
```

For a reference position used in display or observation computation, use the official `virtual_configuration(agent)`. It uses the initial configuration for off-map trains, the current configuration for on-map trains, and the actual arrival configuration for completed trains. Handle reference locations and actual map occupancy separately.

```python
from flatland.envs.agent_utils import virtual_configuration

reference_configuration = virtual_configuration(agent)
```

### 4.2 Running States

`agent.state` returns a `TrainState` enum, describing the same running state as official `info["state"][train_id]`.

| ID | State | Meaning |
|---|---|---|
| 0 | `WAITING` | Waiting for the earliest departure time |
| 1 | `READY_TO_DEPART` | Ready to depart and waiting for a valid departure action |
| 2 | `MALFUNCTION_OFF_MAP` | Malfunction while off the map |
| 3 | `MOVING` | Moving |
| 4 | `STOPPED` | Stopped on the map |
| 5 | `MALFUNCTION` | Malfunction on the map |
| 6 | `DONE` | Reached an allowed final destination configuration |

The project disables malfunction generation and retains the official state enum. Check `agent.state == TrainState.DONE` to identify trains that actually completed their tasks. This state indicates arrival at the destination; intermediate station service requires stop records as well.

### 4.3 Speed and Progress Within a Cell

| Field or method | Meaning |
|---|---|
| `agent.speed_counter.speed` | Current speed-counter value |
| `agent.speed_counter.max_speed` | Maximum speed allowed for this train |
| `agent.speed_counter.distance` | Accumulated progress within the current track cell |
| `agent.speed_counter.is_cell_entry` | Whether the latest step just entered a cell |
| `agent.speed_counter.is_cell_exit(speed)` | Whether the given speed meets the conditions to leave the current cell on the next step |

Speed is measured in cells per environment step. A maximum speed of 1 allows at most one cell per step; a maximum of 0.5 usually takes two steps per cell. Speed and progress use Python's `Fraction` type. Call `float()` for display or conversion to numeric model inputs.

`distance` represents progress within a cell and updates when crossing cells. Interpret speed-counter readings together with the running state: a stopped or malfunctioning train may still retain a nonzero reading. Compare positions and progress before and after a step to determine whether it actually moved.

```python
print(float(agent.speed_counter.speed))
print(float(agent.speed_counter.max_speed))
print(float(agent.speed_counter.distance))
```

## 5. Origins, Destinations, Intermediate Stations, and Timetables

### 5.1 Final Destinations

| Field | Format | Meaning |
|---|---|---|
| `agent.targets` | Set of position-and-direction configurations | All allowed final arrival configurations |
| `agent.target_configuration` | One configuration, or `None` | Configuration actually reached; `None` before completion |
| `agent.arrival_time` | Integer, or `None` | Environment time step of final arrival; `None` before completion |

A destination may allow multiple arrival directions or alternative configurations. Preserve the complete `targets` set when reading goals. Read `target_configuration` to see which configuration the train ultimately reached.

### 5.2 Locations Along a Task

`agent.waypoints` stores task locations as a list of lists. The first outer entry is the origin, the last is the destination, and intermediate entries are intermediate stations. Each inner list contains `Waypoint` alternatives specifying allowed positions and orientations for the same task location.

| Access | Meaning |
|---|---|
| `agent.waypoints[0]` | Origin configurations |
| `agent.waypoints[1:-1]` | Alternative stopping configurations for all intermediate stations |
| `agent.waypoints[-1]` | Alternative final destination configurations |
| `waypoint.position` | Position of one alternative, as `(row, column)` |
| `waypoint.direction` | Required orientation for that alternative |

For example, four outer entries represent an origin, two intermediate stations, and a destination. Three alternatives inside one intermediate station entry provide three configurations where that station can be served. The outer list describes the task plan. The current environment's movement dynamics permit skipping intermediate stations; official rewards assess missed stops and timing deviations from actual records.

### 5.3 Timing Requirements

| Field | Meaning |
|---|---|
| `agent.earliest_departure` | Earliest time step at which the train can depart |
| `agent.latest_arrival` | Latest arrival time step at the final destination |
| `agent.waypoints_earliest_departure` | Earliest departure times for task locations, aligned with outer `waypoints` entries |
| `agent.waypoints_latest_arrival` | Latest arrival times for task locations, aligned with outer `waypoints` entries |

Times are environment steps counted from the start of the episode. For example, a latest arrival of 50 with a current time of 30 leaves 20 steps. `None` means the location has no corresponding requirement. Origins normally have no latest arrival, and destinations normally have no earliest departure.

```python
for alternatives, earliest_departure, latest_arrival in zip(
    agent.waypoints,
    agent.waypoints_earliest_departure,
    agent.waypoints_latest_arrival,
):
    print(alternatives, earliest_departure, latest_arrival)
```

The official state machine enforces the earliest departure time. Intermediate stops, station departure times, and late arrivals follow official task and reward rules. See [experiment environment configuration](../setting/1.experiment_variable.md) for whether these requirements are assessed in an experiment.

### 5.4 Has an Intermediate Station Been Served?

Train objects have no general field for the next station index or completion flags for individual stations. `waypoints` stores the plan, and `state` stores the current running state. Reading these two fields alone does not provide the full history of stops.

When using official `DefaultRewards`, its internal reward object records arrivals, departures, and states encountered. The following access paths depend on this reward component and its internal structure:

| Access path | Content |
|---|---|
| `env.rewards._proxy.arrivals` | Arrival time lists indexed by train ID and position-and-direction configuration |
| `env.rewards._proxy.departures` | Departure time lists indexed by train ID and configuration |
| `env.rewards._proxy.states` | Sets of observed running states indexed by train ID and configuration |

Official rewards use these records to check whether a train had a `STOPPED` state at an allowed stopping configuration, together with its arrival and departure times. Check for these records when changing reward components. `_proxy` is an internal field. These paths identify existing official records; progress assessment must follow the component being used.

## 6. Viewing Train Occupancy Across the Map

`env.agent_positions` is a two-dimensional integer array of shape `(height, width)`. In ordinary grid-track scenarios, each occupied cell stores a train ID, and empty cells store -1. Trains that have not entered the map do not occupy their origins. Trains removed after arrival no longer occupy their destinations.

```python
train_id = int(env.agent_positions[3, 7])
if train_id >= 0:
    occupying_agent = env.agents[train_id]
    print(occupying_agent.state)
```

Use this array for a quick occupancy lookup. For direction, speed, and full state, use the ID to retrieve the train object. Current occupancy describes this instant; next-step occupancy depends on the actions submitted by all trains.

## 7. Shortest Distance to the Final Destination

`env.distance_map.get()` returns an array of shape `(number_of_trains, height, width, 4)`. Its dimensions select train, row, column, and direction. Each value is the shortest track distance from that configuration to any allowed final destination for the train.

```python
distances = env.distance_map.get()
configuration = agent.current_configuration

if configuration is not None:
    (row, column), direction = configuration
    distance = distances[agent.handle, row, column, direction]
    print(distance)
```

Distance is measured in track cells. Unreachable destinations have positive infinity, usually displayed as `inf` in Python. The calculation considers track connections and orientation. Account separately for other trains' current occupancy, waiting, timetables, and intermediate stops. Trains with different maximum speeds can take different amounts of time to cover the same distance.

`env.distance_map.get()` computes or reuses distance data according to official logic. Use this method when reading shortest distances so that the underlying array is calculated when needed.

## 8. Episode Time, End Flags, and Running Settings

| Field | Meaning |
|---|---|
| `env._elapsed_steps` | Steps elapsed in the episode; 0 after reset |
| `env._max_episode_steps` | Episode step limit, available after reset |
| `env.dones` | End flags by train ID; `"__all__"` indicates the episode has ended |
| `env.rewards_dict` | Official rewards from the latest step, keyed by train ID |
| `env.remove_agents_at_target` | Whether trains are removed from the map after reaching destinations |
| `env.acceleration_delta` | Acceleration parameter |
| `env.braking_delta` | Braking parameter |
| `env.obs_builder` | Official observation builder currently in use |

Fields whose names begin with `_` are library internals. These time fields are accessible as listed in Flatland 4.3.0; check them again when upgrading the library.

At the global time limit, the environment sets every train's end flag to True, including trains that have not arrived. Count actual arrivals with `agent.state == TrainState.DONE`. `env.rewards_dict` contains only the latest step's rewards; sum rewards across steps for episode returns.

## 9. Relationship to observations and current_infos

The model input `current_infos` is the current official `info` dictionary under the project's more descriptive variable name. Obtain it directly from the environment with `env.get_info_dict()` when needed.

| Data | Content and access scope |
|---|---|
| `observations[train_id]` | Observation supplied to that train by the selected official builder |
| `current_infos` | Four official auxiliary categories: action requirement, malfunction counter, speed, and state |
| `env` | Full map, all train objects, tasks, timetables, and environment running data |

These data must refer to the same environment instant when choosing an action. After `env.step()`, the environment object has changed. Save the values actually used by the model for historical training data, and use those saved values in later PPO updates. Access to the full map or other trains' information depends on the selected model and experiment conditions.

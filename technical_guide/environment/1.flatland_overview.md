# Flatland 使用教程

[中文](#chinese) | [English](#english)

本项目使用 Flatland 4.3.0。本文按实际操作顺序说明怎样创建环境、运行列车、读取信息、查看结果和保存场景。环境观测和 `info` 使用官方提供的组件与字段。选择观测类型、设置树深度、调整列车数量和配置多速度，都通过现成组件的参数完成。项目当前关闭故障生成，实验范围见 [项目实验设置](../setting/1.experiment_variable.md)。

需要逐个查看动作和观测字段时，阅读 [每步输入输出说明](3.state_and_action.md)。这两份文档中的代码使用已安装的 `cs5446-project` 环境。

## 1. 先了解列车在环境里做什么

Flatland 把铁路画在一个二维网格中。每个轨道格记录列车可以从哪个方向进入、从哪个方向离开。多列车共享这些轨道，每列车有自己的起点、目标和出发／到达时间要求。策略负责选择前进、左转、右转、保持当前控制或停车，环境负责更新位置、速度、故障和轨道占用。

运行环境时，先开始一局，再反复执行“读取信息、选择动作、推进一步”，直到这一局结束。这里“一局”对应强化学习中的 episode；“一步”对应一次 `step()` 调用。每一步推进整个系统的时间，慢车、等待出发的列车和被阻挡的列车都可能暂时留在原位置。

## 2. 创建第一个环境

### 2.1 激活安装好的环境

在终端执行下面的命令，然后用 Python 运行后续示例。

```bash
conda activate cs5446-project
```

### 2.2 创建 30×30 地图和两列车

下面的 `make_env()` 函数用于创建一个小环境，后面的示例可以重复调用它。`env` 表示创建好的环境对象。这里采用官方树观测，树观测会沿轨道查看后续分支，把目标、其他列车和距离等信息组织成树。

```python
from flatland.envs.rail_env import RailEnv
from flatland.envs.rail_generators import sparse_rail_generator
from flatland.envs.line_generators import sparse_line_generator
from flatland.envs.observations import TreeObsForRailEnv


def make_env(observation_builder=None):
    if observation_builder is None:
        observation_builder = TreeObsForRailEnv(max_depth=2)
    return RailEnv(
        width=30,
        height=30,
        number_of_agents=2,
        rail_generator=sparse_rail_generator(
            max_num_cities=2,
            grid_mode=True,
            max_rails_between_cities=2,
            max_rail_pairs_in_city=2,
        ),
        line_generator=sparse_line_generator(),
        obs_builder_object=observation_builder,
        remove_agents_at_target=True,
        random_seed=42,
    )


env = make_env()
observations, info = env.reset(random_seed=42)
```

`width=30` 和 `height=30` 表示地图有 30 列、30 行。`number_of_agents=2` 表示生成两列车。`random_seed=42` 设置随机种子，方便重复检查同一组设置。`remove_agents_at_target=True` 表示完成目标后移除列车在地图上的当前配置，从而释放它占用的轨道资源。

### 2.3 三类生成器各自负责什么

`rail_generator` 生成铁路布局；`line_generator` 生成列车任务，例如起点、目标、途经点和最大速度；`timetable_generator` 生成任务的时间要求以及本局运行时限。示例显式指定前两项，时间表使用环境默认生成器。研究列车数量增加后的拥堵时，应同时记录地图、任务生成参数和时间表，方便各算法运行相同的场景。

| 参数 | 怎样调整 |
|---|---|
| `max_num_cities` | 调整生成的城市数量上限 |
| `grid_mode` | True 时按网格方式布置城市，False 时采用随机布置 |
| `max_rails_between_cities` | 调整城市之间连接轨道的数量上限 |
| `max_rail_pairs_in_city` | 调整城市内部轨道对的数量上限 |
| `obs_builder_object` | 选择官方树观测、全局观测或官方处理后的树观测 |
| `malfunction_generator` | 选择官方故障生成器及故障参数 |
| `rewards` | 选择官方奖励对象，省略时使用 `DefaultRewards()` |

## 3. 开始一局和重复运行同一场景

### 3.1 重新生成一局

调用默认 `reset()` 时，环境重新生成轨道、列车任务和时间表，重置列车状态与运行时间，然后返回初始观测和辅助信息。

```python
observations, info = env.reset(random_seed=42)
```

`observations` 是每列车的观测字典，`info` 保存全部列车的运行辅助信息。列车可能先处于等待状态，运行若干步后才满足出发条件。

### 3.2 重复已有地图和任务

要在相同地图、任务和时间表上重新开始，将两个重新生成选项都设为 False。

```python
observations, info = env.reset(
    regenerate_rail=False,
    regenerate_schedule=False,
)
```

`regenerate_rail` 控制是否重新生成轨道，`regenerate_schedule` 控制是否重新生成任务及时间表。重新生成轨道时，环境也会重新生成任务，以匹配新地图。比较算法时，优先使用保存好的共同场景，并记录场景生成和运行的随机种子。

4.3.0 的内置稀疏轨道与任务生成器组合，在“保留轨道、只重新生成任务”时会缺少任务生成所需的城市提示信息，实际调用可能抛出异常。当前示例使用两种已验证的方式：默认 reset 生成新场景，或两个选项都为 False 重跑已有场景。需要一组固定地图上的不同任务时，先在场景准备阶段生成并保存各组完整场景。

## 4. 给列车动作并推进环境

### 4.1 动作怎么提交

环境用整数给每列车编号。示例中列车编号是 0 和 1。动作同样使用整数编号：0 保持当前控制，1 左转，2 前进，3 右转，4 制动停车。也可以使用官方名称，让代码更容易阅读。

```python
from flatland.envs.rail_env_action import RailEnvActions

actions = {
    0: RailEnvActions.MOVE_FORWARD,
    1: RailEnvActions.STOP_MOVING,
}
next_observations, rewards, dones, next_info = env.step(actions)
```

动作字典中的每个键是列车编号，值是给这列车的动作。省略某列车时，环境为它使用动作 0。左转和右转都以列车的当前朝向为参照。选择停车时使用 `STOP_MOVING`；选择保持当前控制时使用 `DO_NOTHING`。

### 4.2 怎样理解四项返回结果

| 返回变量 | 怎样使用 |
|---|---|
| `next_observations` | 根据列车编号取得更新后的观测，用于下一轮选择动作 |
| `rewards` | 将每列车的本步奖励加到它的累计回报中 |
| `dones` | 用 `dones["__all__"]` 判断是否退出运行循环 |
| `next_info` | 查看下一时刻的动作需求、故障、速度和运行状态 |

列车能否移动由环境检查。例如前方轨道被占用时，前进指令可能使列车等待。记录动作效果时，比较执行前后的当前位置与运行状态。

## 5. 选择官方观测

### 5.1 先用树观测理解信息

树观测从列车附近沿轨道探索，记录分支上的目标距离、其他列车、故障和速度。使用 `TreeObsForRailEnv(max_depth=2)` 时，可以取得根节点和后续两层分支。读取列车 0 的根节点如下。

```python
root = observations[0]
if root is not None:
    print("到目标的最短距离：", root.dist_min_to_target)
    print("故障剩余计数：", root.num_agents_malfunctioning)
    print("速度：", float(root.speed_min_fractional))
```

`None` 表示当前没有可读取的观测对象。树节点有 12 个数值字段，完整解释见 [树观测字段](3.state_and_action.md#32-树观测沿轨道查看后续情况)。根节点的故障字段保存自身故障计数，分支节点的同名字段保存沿途故障列车数量。

### 5.2 神经网络使用官方处理后的树观测

这组官方组件依赖 Ray RLlib，Ray 是并行计算库，RLlib 是其中的强化学习模块。项目的 `environment.yml` 已包含 Ray 2.58.0 及 RLlib 依赖。已有环境需要同步依赖时，在仓库根目录运行下面的命令。

```bash
conda env update -n cs5446-project -f environment.yml
```

给多层感知机使用树观测时，选择官方 `FlattenedNormalizedTreeObsForRailEnv`。多层感知机是接收固定长度数值向量的常见神经网络。这个官方组件负责展开树、填充缺失分支和缩放数值，环境直接返回一维 NumPy 数组。

```python
from flatland.ml.observations.flatten_tree_observation_for_rail_env import (
    FlattenedNormalizedTreeObsForRailEnv,
)

builder = FlattenedNormalizedTreeObsForRailEnv(
    max_depth=2,
    observation_radius=2,
)
env = make_env(observation_builder=builder)
observations, info = env.reset(random_seed=42)

print("列车 0 的观测长度：", observations[0].shape)  # (252,)
print("官方定义的长度：", builder.get_len_flattened())  # 252
```

`.shape` 表示数组各个维度的长度，`(252,)` 表示一维数组中有 252 个数。深度 2 的完整树有 21 个节点，每节点 12 个特征，共 252 个数。官方展开顺序按特征分组：先保存六类沿途距离，再保存最短目标距离，最后保存五类列车信息。`observation_radius=2` 是距离特征缩放参数；具体探索层数由 `max_depth` 控制。

进入 PyTorch 网络时，只做库之间的数据转换，并按网络要求统一数值类型和设备。下面的 `float32` 表示 32 位浮点数，`unsqueeze(0)` 表示增加一个最外层维度，得到“一条样本、252 个特征”的输入。

```python
import torch

actor_input = torch.as_tensor(observations[0], dtype=torch.float32)
actor_input = actor_input.unsqueeze(0)
print(actor_input.shape)  # torch.Size([1, 252])
```

官方还提供 `FlattenedTreeObsForRailEnv`，只展开树并保留原始数值。需要直接向网络提供处理后的观测时，使用带 `Normalized` 的版本。这里的“归一化”指官方组件将数值缩放、截取到适合处理的范围；之后读取原始故障计数时，仍使用官方 info 字段。

### 5.3 使用全局观测查看整张地图

使用 `GlobalObsForRailEnv()` 时，每列车获得三个数组：轨道信息、列车运行信息和目标信息。下面的环境采用 30 行、30 列地图，三个数组的形状分别为 `(30, 30, 16)`、`(30, 30, 5)`、`(30, 30, 2)`。最后的数字表示每格保存多少层信息。

```python
from flatland.envs.observations import GlobalObsForRailEnv

env = make_env(observation_builder=GlobalObsForRailEnv())
observations, info = env.reset(random_seed=42)
rail_map, train_map, target_map = observations[0]
print(rail_map.shape, train_map.shape, target_map.shape)
```

全局数组以当前列车为参照组织部分通道，读取自身方向和目标时使用对应列车的观测。当前项目使用官方树观测、处理后的树观测和全局观测。

## 6. 查看列车状态、位置和任务

### 6.1 读取官方 info

`info` 先按信息类别、再按列车编号组织。例如 `info["malfunction"][0]` 查看列车 0 的故障计数。官方返回四类信息，项目沿用这个结构。

| 读取方法 | 含义 |
|---|---|
| `info["action_required"][0]` | 列车 0 当前是否被标记为需要动作 |
| `info["malfunction"][0]` | 列车 0 的故障剩余计数 |
| `info["speed"][0]` | 列车 0 的速度计数值 |
| `info["state"][0]` | 列车 0 的运行状态 |

速度可能使用 Python 的分数类型表示，例如二分之一。展示或转换成网络数据时，调用 `float(info["speed"][0])` 得到 0.5。故障期间速度计可能保留数值，判断实际运行情况时同时查看状态和位置。

### 6.2 读取位置和目标

`env.agents[0]` 返回列车 0 的对象。位置与方向组合为 `((row, column), direction)`：`row` 是行索引，`column` 是列索引，两个索引都从 0 开始；`direction` 的 0、1、2、3 分别表示北、东、南、西。例如 `((3, 7), 1)` 表示第 4 行、第 8 列、朝东。

```python
agent = env.agents[0]
print("起点：", agent.initial_configuration)
print("当前位置：", agent.current_configuration)
print("可接受的目标：", agent.targets)
print("最早出发时间：", agent.earliest_departure)
print("最晚到达时间：", agent.latest_arrival)
```

`targets` 是可接受终点配置的集合，集合中的元素同时包含位置和允许到达的朝向。完成后，`target_configuration` 保存实际到达的配置，`arrival_time` 保存实际到达时间。`current_configuration` 在列车进入地图前或到站移除后可能为 None，读取位置前先检查。

### 6.3 查看轨道出口与最短路径

`virtual_configuration()` 返回列车用于观测的参考位置和方向：等待时参考起点，行驶时参考当前位置，完成时参考目标。用这个配置查询轨道出口，返回值按北、东、南、西排列，1 表示该方向有可行出口，0 表示没有。

```python
from flatland.envs.agent_utils import virtual_configuration

agent = env.agents[0]
configuration = virtual_configuration(agent)
if configuration is not None:
    (row, column), direction = configuration
    exits = env.rail.get_transitions(configuration)
    print("北、东、南、西的出口：", exits)

    distance_map = env.distance_map.get()
    distance = distance_map[agent.handle, row, column, direction]
    print("到目标的最短轨道距离：", distance)
    print("最短路径：", agent.get_shortest_path(env.distance_map))
```

距离数组按列车编号、地图行、地图列、方向排列。这个最短距离根据轨道连接计算；实际旅行时间还会受到等待、故障和其他列车占用影响。控制策略选择左右动作时，将绝对出口方向换算成列车当前朝向下的相对方向。

## 7. 配置不同列车的最大速度

项目默认支持不同列车具有不同最大速度。通过官方任务生成器的 `speed_ratio_map` 设置速度与抽样比例，例如 `{1.0: 0.5, 0.5: 0.5}` 表示列车以各 50% 的概率获得最大速度 1.0 或 0.5。每个小场景中的实际数量可能有波动，具体比例按实验配置设置。

```python
speed_env = RailEnv(
    width=30,
    height=30,
    number_of_agents=2,
    rail_generator=sparse_rail_generator(max_num_cities=2, grid_mode=True),
    line_generator=sparse_line_generator(
        speed_ratio_map={1.0: 0.5, 0.5: 0.5},
    ),
    obs_builder_object=TreeObsForRailEnv(max_depth=2),
    random_seed=42,
)
speed_observations, speed_info = speed_env.reset(random_seed=42)
```

加速和制动参数使用官方默认值。采样器按环境时间步推进，并结合列车速度、状态和轨道位置管理动作选择。项目当前使用默认无故障配置，官方观测和 info 中的故障字段保留原样。

## 8. 读取奖励和统计完成情况

环境默认使用官方 `DefaultRewards()`，根据到站延误、未出发、未完成和中间站服务情况等计算奖励。普通步骤常见奖励为 0，发生相应惩罚时返回负值。查看本步奖励用 `rewards[train_id]`，查看整局表现则把每步奖励累加起来。

列车运行状态由 `TrainState` 表示。其中 `WAITING` 是等待出发，`READY_TO_DEPART` 是准备出发，`MOVING` 是行驶，`STOPPED` 是停车，`MALFUNCTION` 是地图内故障，`MALFUNCTION_OFF_MAP` 是地图外故障，`DONE` 是完成目标。计算完成率时统计状态为 DONE 的列车，再除以列车总数。

整局结束的条件是全部列车完成，或者达到本局时间上限。用 `dones["__all__"]` 退出循环。超时时环境会将每列车的 done 都置为 True；统计真正完成的列车时仍按运行状态计算。训练管线需要保存这两种结束原因，以便正确计算后续价值估计。

## 9. 运行完整一局

下面的代码接在第 2 节 `make_env()` 定义之后执行。它始终选择前进，用来检查完整交互和结果统计，道岔和共享轨道可能使它等待或超时。第一版 PPO 的动作选择直接启用动作掩码，按 [动作掩码说明](3.state_and_action.md#24-第一版直接使用动作掩码) 读取当前环境并筛选可行选择。

```python
from flatland.envs.rail_env_action import RailEnvActions
from flatland.envs.step_utils.states import TrainState

env = make_env()
observations, info = env.reset(random_seed=42)
train_ids = env.get_agent_handles()
episode_returns = {train_id: 0.0 for train_id in train_ids}
step_count = 0

while True:
    actions = {}
    for train_id in train_ids:
        if info["action_required"][train_id]:
            actions[train_id] = RailEnvActions.MOVE_FORWARD

    next_observations, rewards, dones, next_info = env.step(actions)
    step_count += 1
    for train_id in train_ids:
        episode_returns[train_id] += float(rewards[train_id])

    observations, info = next_observations, next_info
    if dones["__all__"]:
        break

completed_count = sum(
    agent.state == TrainState.DONE for agent in env.agents
)
completion_rate = completed_count / max(len(train_ids), 1)
print("运行步数：", step_count)
print("每列车累计回报：", episode_returns)
print("完成率：", completion_rate)
```

`episode_returns` 保存每列车整局奖励的总和，`step_count` 保存运行步数，`completed_count` 保存到站数量，`completion_rate` 保存完成比例。`max(len(train_ids), 1)` 用于保证分母至少为 1。正式采样时，在动作前后记录观测与辅助信息，并复制需要保留的数据，确保下一次环境更新后历史记录仍正确。

## 10. 查看地图和导出视频

`RenderTool` 负责把环境画成图片。下面使用官方 `PILSVG` 绘图后端，`show=False` 表示在后台生成图片，适合服务器运行。`screen_width` 和 `screen_height` 设置画布大小，单位是像素。

```python
from flatland.utils.rendertools import RenderTool
import imageio.v2 as imageio

renderer = RenderTool(
    env, gl="PILSVG", screen_width=600, screen_height=600,
)
renderer.render_env(show=False, show_observations=False)
frame = renderer.get_image()
imageio.imwrite("flatland.png", frame)
```

`frame` 是渲染出的图片数组。导出整局视频时，每步运行后渲染一次，将图片复制到列表中，再用 `imageio.mimsave("episode.mp4", frames, fps=10)` 写文件。这里的 `frames` 是图片列表，`fps=10` 表示每秒播放 10 张图片。地图重置后重新创建 renderer，以更新轨道背景。训练时按需录制少量评估局，可以减少绘图开销。

## 11. 保存场景供不同算法比较

用官方 `RailEnvPersister` 保存完整场景。准备评估场景时，在 reset 后、执行动作前保存；之后每个算法加载同一文件，再从该场景起点开始运行。

```python
from flatland.envs.persistence import RailEnvPersister

evaluation_env = make_env()
evaluation_env.reset(random_seed=42)
RailEnvPersister.save(
    evaluation_env, "scenario.pkl", save_distance_maps=True,
)

loaded_env, saved_data = RailEnvPersister.load_new(
    "scenario.pkl",
    obs_builder=TreeObsForRailEnv(max_depth=2),
)
loaded_observations, loaded_info = loaded_env.reset(
    regenerate_rail=False,
    regenerate_schedule=False,
)
```

`scenario.pkl` 保存环境场景，`save_distance_maps=True` 表示同时保存最短距离数据。`load_new()` 返回加载后的环境和保存数据字典；代码中的 `saved_data` 保存后者。加载时选择官方观测生成器，并将两个重新生成选项设为 False，便于重复同一地图和任务。另外记录并验证运行种子，确保各算法的比较条件一致。

## 12. 接入训练时按什么顺序准备

先选定一个官方观测组件，并固定其参数。多层感知机策略可以从官方归一化展平树观测开始；查看完整地图时使用官方全局观测。随后将 NumPy 数组转换成 PyTorch 张量，保持列车编号和数据顺序一致。TorchRL 使用 TensorDict 组织张量，接入时将官方输出放入约定的数据容器，并统一数据类型和运行设备。

第一版直接启用动作掩码：每次决策前读取当前轨道、列车位置、朝向和官方运行信息，计算五个动作的允许标记，再让 actor 从允许的动作中采样。掩码由动作选择模块管理，观测和 info 沿用官方格式。详细读取方法和规则见 [动作掩码说明](3.state_and_action.md#24-第一版直接使用动作掩码)。

采样器保存每步的观测、动作掩码、动作、动作对数概率、奖励、结束标记、决策标记和官方 info。PPO 更新时使用采样时保存的掩码计算动作概率，并按决策标记筛选策略样本。使用循环神经网络时，在每局开始时初始化网络记忆。算法所需的训练数据由训练模块管理。

评估时统一地图、列车任务、时间表和速度设置。完成率按真实到站数量统计；旅行时间和延误按出发／到达记录计算。死锁与冲突采用团队确认的判定规则，作为评估结果单独记录。

# Flatland Tutorial

This project uses Flatland 4.3.0. This tutorial follows the practical workflow: create an environment, run trains, read information, inspect results, and save scenarios. Observations and `info` use official components and fields. Select observation types, tree depth, train counts, and multiple speeds through existing component parameters. Malfunction generation is currently disabled. See [experiment settings](../setting/1.experiment_variable.md) for the scope.

For individual action and observation fields, see [the step input/output guide](3.state_and_action.md). Examples in both documents use the installed `cs5446-project` environment.

## 1. What Trains Do in the Environment

Flatland represents a railway as a two-dimensional grid. Each track cell records allowed entry and exit directions. Multiple trains share the tracks, with each train having its own origin, destinations, and departure/arrival timing requirements. The policy chooses forward, left, right, retain current control, or stop. The environment updates positions, speeds, malfunctions, and track occupancy.

Start an episode, then repeatedly read information, choose actions, and advance one step until it ends. An episode is one complete run; a step is one `step()` call. Each step advances time for the entire system. Slow trains, trains waiting to depart, and blocked trains may stay in the same position temporarily.

## 2. Creating Your First Environment

### 2.1 Activate the Installed Environment

Run the following command in a terminal, then use Python for the examples that follow.

```bash
conda activate cs5446-project
```

### 2.2 Create a 30×30 Map with Two Trains

The `make_env()` function below creates a small environment and can be reused later. `env` is the resulting environment object. This example uses the official tree observation, which explores upcoming track branches and organizes targets, other trains, and distances into a tree.

```python
from flatland.envs.rail_env import RailEnv
from flatland.envs.rail_generators import sparse_rail_generator
from flatland.envs.line_generators import sparse_line_generator
from flatland.envs.observations import TreeObsForRailEnv


def make_env(observation_builder=None):
    if observation_builder is None:
        observation_builder = TreeObsForRailEnv(max_depth=2)
    return RailEnv(
        width=30,
        height=30,
        number_of_agents=2,
        rail_generator=sparse_rail_generator(
            max_num_cities=2,
            grid_mode=True,
            max_rails_between_cities=2,
            max_rail_pairs_in_city=2,
        ),
        line_generator=sparse_line_generator(),
        obs_builder_object=observation_builder,
        remove_agents_at_target=True,
        random_seed=42,
    )


env = make_env()
observations, info = env.reset(random_seed=42)
```

`width=30` and `height=30` give 30 columns and 30 rows. `number_of_agents=2` generates two trains. `random_seed=42` sets a random seed to make repeated checks convenient. `remove_agents_at_target=True` removes a completed train's current on-map configuration, releasing its occupied track resources.

### 2.3 Responsibilities of the Three Generators

`rail_generator` generates the railway layout. `line_generator` generates train tasks, including origins, destinations, waypoints, and maximum speeds. `timetable_generator` generates timing requirements and the episode time limit. The example specifies the first two and uses the default timetable generator. When studying congestion as train counts increase, record map and task parameters together with timetables so that algorithms can run the same scenarios.

| Parameter | How to configure it |
|---|---|
| `max_num_cities` | Maximum number of generated cities |
| `grid_mode` | True places cities on a grid; False places them randomly |
| `max_rails_between_cities` | Maximum number of connecting tracks between cities |
| `max_rail_pairs_in_city` | Maximum number of track pairs within cities |
| `obs_builder_object` | Official tree, global, or processed tree observation |
| `malfunction_generator` | Official malfunction generator and its parameters |
| `rewards` | Official reward object; defaults to `DefaultRewards()` when omitted |

## 3. Starting an Episode and Repeating a Scenario

### 3.1 Generate a New Episode

A default `reset()` regenerates tracks, train tasks, and timetables, resets train states and running time, and returns initial observations and auxiliary information.

```python
observations, info = env.reset(random_seed=42)
```

`observations` contains each train's observation. `info` contains running information for all trains. Trains may initially wait and become eligible to depart after several steps.

### 3.2 Reuse the Existing Map and Tasks

To restart with the same map, tasks, and timetable, set both regeneration options to False.

```python
observations, info = env.reset(
    regenerate_rail=False,
    regenerate_schedule=False,
)
```

`regenerate_rail` controls track regeneration; `regenerate_schedule` controls task and timetable regeneration. Regenerating tracks also regenerates tasks to match the new map. For algorithm comparisons, prefer saved common scenarios and record generation and running seeds.

In Flatland 4.3.0, the built-in sparse track/task generator combination may lack the city hints needed when retaining tracks and regenerating only tasks, causing an exception. These examples use two verified modes: a default reset for a new scenario, or both flags False to replay an existing scenario. For different tasks on a fixed map, generate and save complete scenarios during scenario preparation.

## 4. Submitting Actions and Advancing the Environment

### 4.1 Submit Actions

The environment assigns each train an integer ID. This example uses 0 and 1. Actions also have integer IDs: 0 retains current control, 1 turns left, 2 moves forward, 3 turns right, and 4 brakes to stop. Official names make the code easier to read.

```python
from flatland.envs.rail_env_action import RailEnvActions

actions = {
    0: RailEnvActions.MOVE_FORWARD,
    1: RailEnvActions.STOP_MOVING,
}
next_observations, rewards, dones, next_info = env.step(actions)
```

Each dictionary key is a train ID, and its value is that train's action. An omitted train receives action 0. Left and right are relative to the train's current orientation. Use `STOP_MOVING` to stop and `DO_NOTHING` to retain current control.

### 4.2 Interpret the Four Return Values

| Return variable | How to use it |
|---|---|
| `next_observations` | Updated observations by train ID for the next decision |
| `rewards` | Add each train's step reward to its cumulative return |
| `dones` | Check `dones["__all__"]` to exit the running loop |
| `next_info` | Action requirement, malfunction, speed, and running state at the next instant |

The environment checks whether trains can move. For example, an occupied track ahead may cause a forward action to wait. Compare positions and running states before and after the action to record its effect.

## 5. Choosing Official Observations

### 5.1 Understand Information with Tree Observations

Tree observations explore tracks near a train and record target distances, other trains, malfunctions, and speeds along branches. `TreeObsForRailEnv(max_depth=2)` provides a root and two further branch levels. Read train 0's root as follows.

```python
root = observations[0]
if root is not None:
    print("Shortest distance to target:", root.dist_min_to_target)
    print("Remaining malfunction counter:", root.num_agents_malfunctioning)
    print("Speed:", float(root.speed_min_fractional))
```

`None` means no observation object is currently available. Tree nodes contain 12 numeric fields; see [tree observation fields](3.state_and_action.md#32-tree-observations-exploring-upcoming-tracks). At the root, the malfunction field stores the train's own counter. At branch nodes, it stores the number of malfunctioning trains along that branch.

### 5.2 Use Official Processed Tree Observations for Neural Networks

These official components depend on Ray RLlib. Ray supports parallel computation, and RLlib is its reinforcement learning module. The project's `environment.yml` already includes Ray 2.58.0 and RLlib dependencies. To synchronize an existing environment, run this command from the repository root.

```bash
conda env update -n cs5446-project -f environment.yml
```

For a multilayer perceptron, use official `FlattenedNormalizedTreeObsForRailEnv`. A multilayer perceptron is a common network that takes fixed-length numeric vectors. This component flattens the tree, fills missing branches, and scales values. The environment returns a one-dimensional NumPy array directly.

```python
from flatland.ml.observations.flatten_tree_observation_for_rail_env import (
    FlattenedNormalizedTreeObsForRailEnv,
)

builder = FlattenedNormalizedTreeObsForRailEnv(
    max_depth=2,
    observation_radius=2,
)
env = make_env(observation_builder=builder)
observations, info = env.reset(random_seed=42)

print("Train 0 observation shape:", observations[0].shape)  # (252,)
print("Official feature count:", builder.get_len_flattened())  # 252
```

`.shape` gives the length of each array dimension. `(252,)` means a one-dimensional array of 252 numbers. A complete depth-2 tree has 21 nodes, with 12 features each, giving 252 values. Official flattening groups features: six types of distances along branches first, shortest target distances next, and five train-information features last. `observation_radius=2` controls distance scaling; `max_depth` controls exploration levels.

Before entering a PyTorch network, convert data between libraries and use the numeric type and device required by the network. `float32` means 32-bit floating point. `unsqueeze(0)` adds an outer dimension, giving one sample with 252 features.

```python
import torch

actor_input = torch.as_tensor(observations[0], dtype=torch.float32)
actor_input = actor_input.unsqueeze(0)
print(actor_input.shape)  # torch.Size([1, 252])
```

Official `FlattenedTreeObsForRailEnv` also exists and flattens the tree while preserving raw values. Use the `Normalized` version for processed network input. Here, normalization means scaling and clipping values to suitable ranges. Read raw malfunction counters from official info fields when needed.

### 5.3 View the Entire Map with Global Observations

With `GlobalObsForRailEnv()`, each train receives three arrays: tracks, train running information, and targets. For the 30-row, 30-column map below, their shapes are `(30, 30, 16)`, `(30, 30, 5)`, and `(30, 30, 2)`. The last dimension is the number of information channels per cell.

```python
from flatland.envs.observations import GlobalObsForRailEnv

env = make_env(observation_builder=GlobalObsForRailEnv())
observations, info = env.reset(random_seed=42)
rail_map, train_map, target_map = observations[0]
print(rail_map.shape, train_map.shape, target_map.shape)
```

Some global channels are relative to the observing train. Use that train's observation to read its own direction and targets. This project uses official tree, processed tree, and global observations.

## 6. Reading Train States, Positions, and Tasks

### 6.1 Read Official info

`info` is organized by information category and then train ID. For example, `info["malfunction"][0]` reads train 0's malfunction counter. The project retains the four official categories.

| Access | Meaning |
|---|---|
| `info["action_required"][0]` | Whether train 0 is currently marked as requiring an action |
| `info["malfunction"][0]` | Train 0's remaining malfunction counter |
| `info["speed"][0]` | Train 0's speed-counter value |
| `info["state"][0]` | Train 0's running state |

Speed may use Python's fraction type, such as one-half. For display or network conversion, `float(info["speed"][0])` gives 0.5. The speed counter may retain a value during a malfunction, so check state and position as well when assessing actual movement.

### 6.2 Read Positions and Targets

`env.agents[0]` returns train 0's object. Position and direction use `((row, column), direction)`. Row and column indices start at 0. Direction IDs 0, 1, 2, and 3 mean north, east, south, and west. For example, `((3, 7), 1)` means fourth row, eighth column, facing east.

```python
agent = env.agents[0]
print("Origin:", agent.initial_configuration)
print("Current position:", agent.current_configuration)
print("Allowed destinations:", agent.targets)
print("Earliest departure:", agent.earliest_departure)
print("Latest arrival:", agent.latest_arrival)
```

`targets` is a set of allowed destination configurations, each including position and arrival orientation. After completion, `target_configuration` stores the actual arrival configuration and `arrival_time` stores the actual arrival time. `current_configuration` may be None before entering the map or after removal at arrival. Check it before reading the position.

### 6.3 Read Track Exits and Shortest Paths

`virtual_configuration()` returns the reference position and direction used for observations: the origin while waiting, the current position while running, and the destination after completion. Query track exits using this configuration. Results are ordered north, east, south, west; 1 indicates an available exit, and 0 indicates none.

```python
from flatland.envs.agent_utils import virtual_configuration

agent = env.agents[0]
configuration = virtual_configuration(agent)
if configuration is not None:
    (row, column), direction = configuration
    exits = env.rail.get_transitions(configuration)
    print("North, east, south, west exits:", exits)

    distance_map = env.distance_map.get()
    distance = distance_map[agent.handle, row, column, direction]
    print("Shortest track distance to target:", distance)
    print("Shortest path:", agent.get_shortest_path(env.distance_map))
```

Distance arrays are indexed by train ID, row, column, and direction. This shortest distance follows track connections. Actual travel time also depends on waiting, malfunctions, and other trains' occupancy. Convert absolute exit directions to relative directions when selecting left and right actions.

## 7. Configuring Different Maximum Speeds

The project supports different maximum speeds across trains by default. Set speeds and assignment probabilities through the official task generator's `speed_ratio_map`. For example, `{1.0: 0.5, 0.5: 0.5}` assigns each train maximum speed 1.0 or 0.5 with a 50% probability each. Actual counts can vary in small scenarios. Choose probabilities in the experiment configuration.

```python
speed_env = RailEnv(
    width=30,
    height=30,
    number_of_agents=2,
    rail_generator=sparse_rail_generator(max_num_cities=2, grid_mode=True),
    line_generator=sparse_line_generator(
        speed_ratio_map={1.0: 0.5, 0.5: 0.5},
    ),
    obs_builder_object=TreeObsForRailEnv(max_depth=2),
    random_seed=42,
)
speed_observations, speed_info = speed_env.reset(random_seed=42)
```

Acceleration and braking use official defaults. The sampler advances by environment steps and manages action selection using speeds, states, and track positions. The project currently uses the default configuration without malfunctions and retains official malfunction fields in observations and info.

## 8. Reading Rewards and Measuring Completion

By default, the environment uses official `DefaultRewards()`, which accounts for arrival delay, failure to depart, unfinished tasks, and intermediate station service. Ordinary steps commonly return 0, while penalties return negative rewards. Read step rewards with `rewards[train_id]` and sum them across steps for episode performance.

`TrainState` represents running states: `WAITING` means waiting to depart, `READY_TO_DEPART` means ready to depart, `MOVING` means running, `STOPPED` means stopped, `MALFUNCTION` means an on-map malfunction, `MALFUNCTION_OFF_MAP` means an off-map malfunction, and `DONE` means the destination was reached. Compute completion rate as the number of DONE trains divided by total trains.

An episode ends when all trains finish or the episode time limit is reached. Exit the loop using `dones["__all__"]`. At timeout, every train's done flag becomes True; count actual completion using running states. The training pipeline must preserve both ending causes for correct subsequent value estimation.

## 9. Running a Complete Episode

Run this example after defining `make_env()` in Section 2. It always selects forward to check the full interaction and result statistics. Switches and shared tracks may cause waiting or timeout. The first PPO version directly enables action masks; read the current environment and filter choices according to [the action mask guide](3.state_and_action.md#24-enable-action-masks-in-the-first-version).

```python
from flatland.envs.rail_env_action import RailEnvActions
from flatland.envs.step_utils.states import TrainState

env = make_env()
observations, info = env.reset(random_seed=42)
train_ids = env.get_agent_handles()
episode_returns = {train_id: 0.0 for train_id in train_ids}
step_count = 0

while True:
    actions = {}
    for train_id in train_ids:
        if info["action_required"][train_id]:
            actions[train_id] = RailEnvActions.MOVE_FORWARD

    next_observations, rewards, dones, next_info = env.step(actions)
    step_count += 1
    for train_id in train_ids:
        episode_returns[train_id] += float(rewards[train_id])

    observations, info = next_observations, next_info
    if dones["__all__"]:
        break

completed_count = sum(
    agent.state == TrainState.DONE for agent in env.agents
)
completion_rate = completed_count / max(len(train_ids), 1)
print("Steps:", step_count)
print("Per-train returns:", episode_returns)
print("Completion rate:", completion_rate)
```

`episode_returns` stores total rewards per train, `step_count` counts running steps, `completed_count` counts arrivals, and `completion_rate` is the completed fraction. `max(len(train_ids), 1)` keeps the denominator at least 1. During formal sampling, record observations and auxiliary information before and after actions, copying data that must be preserved so that later environment updates leave historical records intact.

```python
from flatland.utils.rendertools import RenderTool
import imageio.v2 as imageio

renderer = RenderTool(

```

`frame` is the rendered image array. To export a video, render after each step, copy images into a list, then write them with `imageio.mimsave("episode.mp4", frames, fps=10)`. `frames` is the image list, and `fps=10` plays ten images per second. Recreate the renderer after resetting the map to update its track background. Recording a few evaluation episodes as needed reduces rendering overhead during training.

Record and verify running seeds as well to maintain common comparison conditions.

## 12. Preparing for Training

First select an official observation component and fix its parameters. A multilayer perceptron policy can start with official normalized flattened tree observations. Use official global observations for full-map information. Convert NumPy arrays to PyTorch tensors while keeping train IDs and data order consistent. TorchRL organizes tensors in TensorDicts; place official outputs in the agreed container and use consistent numeric types and devices.

Enable action masks in the first version. Before each decision, read current tracks, positions, orientations, and official running information, compute permission flags for all five actions, and let the Actor sample from allowed actions. The action selection module manages masks. Observations and info retain official formats. See [the action mask guide](3.state_and_action.md#24-enable-action-masks-in-the-first-version) for access methods and rules.

The sampler saves observations, masks, actions, action log probabilities, rewards, end flags, decision flags, and official info at each step. PPO updates compute probabilities using saved sampling masks and select policy samples using decision flags. With recurrent networks, initialize network memory at the start of each episode. The training module manages algorithm-specific training data.

Use the same maps, train tasks, timetables, and speed settings for evaluation. Calculate completion rate from actual arrivals, and travel time and delay from departure/arrival records. Use team-agreed rules for deadlocks and conflicts and record them separately as evaluation results.
